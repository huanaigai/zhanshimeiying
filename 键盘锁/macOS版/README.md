# KeyLock 键盘锁 · macOS 版

锁定后，**除解锁快捷键外，所有键盘按键一律无响应**。界面中英文切换，深色 / 浅色主题。

## 🔑 最重要的一步：辅助功能权限

macOS 不允许普通程序随便监听键盘。KeyLock 需要**「辅助功能」**权限：

1. 第一次运行 KeyLock，它会请求授权（或者你直接去设置里加）。
2. 打开 **系统设置 → 隐私与安全性 → 辅助功能**。
3. 把 **KeyLock**（源码运行时是「终端」或「Python」）勾上。
4. **重新启动 KeyLock** —— 权限是进程启动时检查的，不重启不生效。

没授权的话，拦截引擎会启动失败并弹窗告诉你原因，界面本身照常能用（你还能改设置）。

> 用源码运行时，授权对象是**运行它的那个终端**（Terminal / iTerm），不是 Python 本身。
> 打包成 `.app` 之后授权对象才是 KeyLock.app。

## 上机检查清单

第一次在 Mac 上跑，建议按这个顺序验：

| # | 做什么 | 期望 |
| --- | --- | --- |
| 1 | `python3 selftest.py` | 全部通过，最后说明跳过了哪一节 |
| 2 | `python3 main.py` | 窗口正常显示（先不管好看不好看，能显示就行） |
| 3 | 点大开关 | 键盘立刻失效，敲什么都没反应 |
| 4 | 按 `Ctrl + Option + L` | 键盘立刻恢复 |
| 5 | 锁上后点开关（鼠标） | 也能解锁 |
| 6 | 打开「修改」改快捷键 | 按新组合键，录像能录到 |
| 7 | 把倒计时设成 3 秒，点开关 | 显示 3、2、1 后锁定 |
| 8 | **设密码后再锁，点开关** | 密码框能打字 → **这是最可能出问题的一项**（依赖前台窗口 PID 查询） |

## 工作原理

在 HID 层挂一个 `CGEventTap`（`CGEventTapCreate` + `kCGHIDEventTap`），回调里返回 `NULL`
就把这次按键彻底吞掉 —— 任何程序都收不到。和 Windows 版的 `WH_KEYBOARD_LL` 是同一个思路。

有两个地方和 Windows 版不一样，都写在 `keyboard_blocker.py` 的注释里：

1. **修饰键事件必须放行。** macOS 的按键事件自带完整的修饰键 flags，只要修饰键本身
   正常送达系统，后续事件的 flags 就是准的。反过来，如果我们把 Control 的按下也吞掉，
   系统就不知道 Control 按下了，后面那个 L 事件的 flags 里就不会有 Control ——
   解锁快捷键反而认不出来。
2. **tap 被系统关掉后要自己重新打开。** 回调太慢时 macOS 会发
   `kCGEventTapDisabledByTimeout`，不处理的话拦截会静悄悄地失效。

## 文件结构

| 文件 | 说明 |
| --- | --- |
| `main.py` | 入口：命令行参数、单实例、崩溃兜底 |
| `app.py` | 控制器：把配置 / 引擎 / 界面串起来 |
| `keyboard_blocker.py` | 拦截引擎。**核心判断 `decide()` 是纯函数**，可以脱离 macOS 单测 |
| `quartz.py` | Quartz / CoreFoundation 的 ctypes 绑定（只做 FFI，不放业务逻辑） |
| `ui.py` | 界面。**和 Windows 版是同一份文件**，只差三处 macOS 适配 |
| `config.py` | 配置。**和 Windows 版是同一份文件**，只差 `data_dir()` 按平台分流 |
| `i18n.py` | 文案表。**和 Windows 版基本同一份**，改了托盘/设备相关措辞 |
| `autostart.py` | 开机自启（LaunchAgent plist） |
| `selftest.py` | 自检，任何平台都能跑 |
| `run.command` | 双击运行 |
| `build_app.sh` | 打包成 .app |

`ui.py` / `config.py` / `i18n.py` 是从 Windows 版复制过来的，**尽量保持一致**。
以后改 Windows 版的时候记得同步 —— 好处是两边共用一套界面和配置逻辑，不会各写各的。

配置文件在 `~/Library/Application Support/KeyLock/`。

## 已知限制

- **`⌘ + Tab`、`⌘ + Q` 这类系统级组合在锁定状态下会被拦住**（在 tap 层就被吞了），
  这是预期行为。
- **`⌘ + ⌥ + Esc`（强制退出）拦不住** —— 和 Windows 上的 `Ctrl+Alt+Del` 一样，
  那是系统留的逃生通道。
- **触摸板 / 鼠标不受影响**，和 Windows 版一致。
- 打包成 `.app` 后，**每次重新打包都会让辅助功能授权失效**（签名变了），
  需要重新去设置里勾一次。开发期用源码运行可以避免这个折腾。
